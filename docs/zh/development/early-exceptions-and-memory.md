# 早期异常与物理内存

## 描述符表

SceneOS 启动后安装自有 GDT：空描述符、64 位内核代码段、内核数据段和
16 字节 TSS 描述符。
代码段和数据段描述符预置 accessed 位。TSS 描述符位于可写 GDT 中，因为
`LTR` 会将可用 TSS 描述符更新为 busy 状态。

TSS 提供 32 KiB Ring 0 栈，以及四个 16 KiB IST 栈：双重故障使用 IST1、
NMI 使用 IST2、机器检查使用 IST3，异常自测可临时使用 IST4。I/O bitmap
偏移设置在 TSS 末尾，当前不允许用户态直接执行端口 I/O。

IDT 当前安装向量 0–31。NASM 入口统一有无硬件错误码的栈布局，保存通用
寄存器后把 `scene_exception_frame` 交给 C 分派器。当前异常策略是输出向量、
错误码、RIP、RFLAGS 和 IST 索引后停机。进入用户态前还需实现可恢复中断
返回路径和按线程更新 `RSP0`。

## 早期物理页分配器

启动适配层只把 Limine 标记为 usable 的区域复制到内核自有结构。每个区域
开头保存该区域自己的分配位图，因此元数据随物理内存规模增长而分散扩展，
不会因最高物理地址中的大空洞产生巨型全局位图。分配器：

- 使用 4 KiB 页；
- 对区域边界向内对齐；
- 保留物理地址前 1 MiB；
- 跳过溢出或空区域；
- 以布尔返回值区分分配成功和耗尽；
- 支持页释放、拒绝未对齐地址、元数据页和重复释放；
- 释放页会更新搜索提示，可被后续分配复用。

当前仍缺少任意保留区登记、连续多页分配、并发保护和更完整的统计。

## 分页

分页模块读取当前 CR3，并通过 HHDM 访问 Limine 建立的四级页表。新映射会按需
分配并清零中间页表，支持 supervisor/user、writable 和 executable 标志，
默认数据页设置 NX。接口拒绝非规范地址、未对齐地址、巨页中间项及覆盖已有
叶项，并在映射后执行 `invlpg`。

初始化时 SceneOS 递归克隆所有存在的四级页表结构，保留叶物理映射和巨页，
再装载新的 CR3。别名表通过克隆记录复用，避免递归映射导致循环。切换以后
新增映射只修改 SceneOS 自有页表。

分页层支持取消 4 KiB 叶映射、执行 `invlpg` 并返回原物理页，调用者可将其
归还物理分配器。空的中间页表回收、巨页拆分和完整地址空间销毁仍是后续工作。

## 早期内核堆

内核堆从 `0xffffc00000000000` 开始，最大预留 16 MiB，按 4 页增长并向分页
模块申请物理页。每个块保存双向链表元数据；分配时支持 2 的幂次对齐和尾部
拆分，释放时验证前缀与块魔数、拒绝重复释放，并向前后合并相邻空闲块。

测试覆盖跨页读写、拆分、合并、无扩容复用、全部释放归零和重复释放拒绝。
当前还没有并发锁、slab/尺寸类、内存毒化，也不会把堆尾空闲页取消映射后归还
物理分配器。

页故障诊断会报告错误码、RIP、RFLAGS、CR2、读写类型和用户/内核权限级别。

## 验证

```text
python tools/scenectl.py smoke
python tools/scenectl.py smoke --exception
python tools/scenectl.py smoke --page-fault
```

这些命令使用 QEMU UEFI 虚拟 FAT 介质，无需 ISO 工具。普通测试验证分页、
跨页堆和启动完成标志；异常测试触发 `int3`；页故障测试写入未映射地址，
验证带硬件错误码的入口和 CR2 诊断。
