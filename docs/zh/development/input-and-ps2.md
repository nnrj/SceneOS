# 输入核心与 PS/2 键盘

输入核心把设备原始字节与使用者分离。`input.c` 维护一个含 64 个槽位的
`scene_input_event` 环形队列；首版生产者是键盘 IRQ handler，消费者是启动期
内核代码。为区分满与空会保留一个槽位，因此最多积压 63 个事件。溢出时丢弃
新事件并增加可查询的计数器。

首版只假定单生产者、单消费者、单 BSP 和 x86 有序内存模型，并不是可直接用于
SMP 的通用队列。加入其他生产者或用户态消费者之前，必须补充明确的原子内存
序，以及事件扇出或焦点路由策略。

i8042 驱动在配置期间禁用第一端口、清理陈旧输出，启用第一端口中断与翻译、
开启键盘扫描，然后通过核心 IRQ 注册表附着 IRQ1。所有轮询都有上限，失败时
退出初始化而不会永久卡死。中断 handler 每次最多读取 16 个键盘字节，跳过辅助
设备数据，解码常用 Set 1 与扩展键，维护左右修饰键和 Caps Lock，并发布按下、
释放与重复事件。

驱动刻意不生成字符。键盘布局、Shift/Caps 规则、Unicode 组合、死键和输入法
属于语义按键事件之上的文本输入服务。当前还不支持 Pause/Print Screen 特殊
序列、LED、热插拔恢复、鼠标或多键盘。

执行 `python tools/scenectl.py smoke --keyboard --timeout 10` 会构建自测内核，
并通过 QEMU Monitor 注入 `A`。测试通过表示模拟设备、IRQ1 路由、解码器和队列
这一整条链路可用。
