# 愿景与设计原则

SceneOS 是面向桌面、自动化和长期兼容的现代操作系统实验项目。它不是
NNOS 的原地 64 位升级，而是以 NNOS 的功能、交互和故障记录为参考进行的
全新实现。

## 产品定位

SceneOS 的产品方向可概括为：

> Unix-friendly core，Windows-friendly desktop，AI-friendly automation。

- 原生命令行遵循 Unix 风格：路径分隔符为 `/`，系统区分大小写，命令支持
  管道、重定向和组合。
- 桌面学习 Windows 的窗口管理、任务栏、开始入口、文件管理、快捷键、
  安装体验和长期兼容文化。
- GUI 和 CLI 都是一等交互界面。GUI 与内核解耦，但不是可忽略的附属品。
- AI 是默认系统服务和结构化自动化入口，但不是内核代码。
- 初期只支持 x86-64，同时保持清晰的架构隔离边界，为未来 ARM64 留出空间。

## 内核原则

- 初期采用模块化单体内核，远期允许演化为混合内核。
- 内核模块通过不透明句柄和明确接口交互，不共享任意内部结构。
- GUI、桌面、AI、高层网络协议等从一开始运行在用户态。
- 串口日志、panic 和可复现虚拟机测试属于基础设施，不是调试补丁。
- ELF64 是 SceneOS 原生可执行格式；NNOS `.nex` 只作为远期兼容研究对象。

## 工程原则

- Windows、Linux 使用同一份 CMake 项目和相同的构建语义。
- IDE 仅提供便利，不能成为构建前提。
- 一键运行是正式受支持的入口。
- 自动部署不得静默修改注册表、全局 PATH、系统目录或 shell 配置。
- 工具和第三方依赖必须锁定版本并校验摘要。

## 兼容性阶段

1.0 之前允许主动修正 API/ABI，仓库内调用方同步修改。第一个稳定版之后，
兼容性成为发布门槛：公共 ABI 以只增不改为原则，旧程序纳入持续回归测试，
必要时通过并列运行库、兼容清单和用户态 shim 保持运行。
