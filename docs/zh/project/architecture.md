# 系统架构

## 分层

```text
应用与桌面
  ├─ Windows 风格桌面 Shell、文件管理器、设置
  ├─ Unix 风格终端与命令行工具
  └─ 应用程序

用户态系统服务
  ├─ init / 服务管理
  ├─ 窗口服务器与合成器
  ├─ AI 服务 aid 与 JSON 操作网关
  └─ 网络、存储等可迁移服务

系统 ABI
  ├─ ELF64 装载
  ├─ 系统调用
  ├─ IPC、句柄、权限与审计
  └─ libc / Scene SDK

模块化单体内核
  ├─ 调度、进程、线程
  ├─ 物理内存、页表、虚拟内存
  ├─ VFS、块设备和核心驱动
  └─ 中断、定时器、PCI、ACPI

架构与平台
  └─ arch/x86_64（未来可增加 arch/aarch64）
```

## GUI 与 headless

内核不依赖 GUI。SceneOS 定义两个正式启动形态：

- `desktop`：默认产品模式，启动合成器、桌面 Shell 和系统应用。
- `console`：救援、调试、服务器和无图形设备模式。

桌面、命令行和内核分别拥有独立里程碑及发布质量门槛。headless 可运行不代表
GUI 可以被延期为无限期的“可选组件”。

## 架构兼容边界

核心代码不得直接使用 CR3、端口 I/O、APIC 寄存器或 x86 页表格式。以下操作
由 `arch/<architecture>` 提供：

- 中断控制、停机和 CPU-local 状态；
- 页表、TLB 与地址空间切换；
- 上下文切换；
- 原子操作和内存屏障；
- 架构定时器和中断控制器。

这些接口在编译期绑定，不要求增加运行时虚调用。

## 单体到混合内核

初期模块通过函数调用。接口需具有可迁移属性：请求对象、错误码、生命周期、
所有权、超时和取消语义明确，避免传递任意内部指针。以后可将选定模块替换为
IPC 服务，而无需同时重写全部调用方。项目不承诺轻松转换成纯微内核，远期
目标是按可靠性和性能选择隔离边界。

## 当前实现状态

M1 已安装 SceneOS 自有 x86-64 GDT、TSS 和异常 IDT。双重故障、NMI、机器
检查分别使用独立 IST 栈，诊断异常也可通过专用 IST 栈验证真实切栈。启动适配层将 Limine 内存图
转换为架构无关的可用物理区，核心内存模块以 4 KiB 页提供早期分配，并保留
前 1 MiB。物理分配器使用每区域位图并支持释放。分页模块克隆 Limine 的活动
四级页表并切换到 SceneOS 自有 CR3，支持 4 KiB 映射、取消映射和物理页归还。
内核堆位于 `0xffffc00000000000`，按需提交物理页，并支持块拆分、相邻空闲块
合并、释放与复用。中间页表回收、堆尾物理页归还、并发分配、slab/对象缓存、
按线程更新 TSS RSP0 尚未实现。M2 已建立 8259A 兼容初始化，并从 ACPI MADT
发现 Local APIC、IOAPIC 和 IRQ 覆盖关系；默认 Q35 路径把 100 Hz PIT IRQ
路由到 BSP Local APIC。共享 ACPI 查询层校验 RSDP、XSDT/RSDT 和目标表；核心
时间层优先使用 64 位 HPET 主计数器，缺失时以 PIT tick 校准 TSC，并统一提供
纳秒单调时间。固定 32 项的小顶堆定时器队列支持调度、取消和在非 IRQ 上下文
分派到期回调。跨 CPU 时钟同步、Local APIC timer、动态队列容量和通用驱动
IRQ 注册仍待实现。
