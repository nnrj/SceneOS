# 兼容性政策

## 稳定版之前

- 不承诺跨提交 API/ABI 兼容。
- 正确性、边界清晰和可维护性优先。
- API 变化必须在同一变更中更新仓库内调用方和两种语言文档。
- 不为尚未发布的接口积累永久兼容负担。

## 1.0 及稳定版之后

- 系统调用 ABI 以只增不改为原则。
- 公共结构不得暴露内核内部布局。
- 公共库具有独立 ABI 主版本，不兼容版本可并列安装。
- 废弃接口先提供诊断、迁移说明和合理期限的 shim。
- 配置、数据格式、命令行为、错误码和窗口协议也属于兼容面。
- CI 保留历史应用二进制和典型数据，持续验证新版本。
- 严重安全问题可以打破兼容，但必须记录影响和迁移方法。

## Windows 与 Linux 兼容层

SceneOS 原生语义保持 Unix 风格。盘符、反斜杠、不区分大小写和外部系统调用
由独立用户态 compatibility personality 翻译。稳定版前不承诺 Windows 或
Linux 二进制兼容；首先保证 SceneOS 自身版本间的长期兼容。
